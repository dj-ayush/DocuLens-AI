# DocuLens AI

DocuLens AI is a document question-answering application built with Streamlit and FastAPI. A user uploads one PDF, asks questions about it, and receives a grounded answer with page-level citations.

## Problem Statement

Long documents are difficult to search manually. DocuLens AI extracts a PDF's text, preserves page metadata, retrieves only relevant evidence for each question, and uses an LLM to produce a simple answer without sending the complete document to the model.

## Key Features

- One active PDF document at a time
- Configurable file-size and page-count limits
- Page-aware extraction and chunking
- HuggingFace embeddings with Chroma vector storage
- Hybrid semantic and keyword retrieval
- Configurable relevance threshold and result limits
- Groq as the default LLM provider
- Optional Gemini provider
- Grounded answers with backend-owned page citations
- Lightweight follow-up question context
- Replacement isolation so old document vectors are removed
- Simple errors without API keys or stack traces in the UI

## System Architecture

```text
Streamlit frontend
        |
        v
FastAPI API
        |
        +--> PDF validation and page extraction
        |          |
        |          v
        |      Chunking + page metadata
        |          |
        |          v
        |      HuggingFace embeddings --> Chroma
        |                                      |
        +--> User question --> hybrid retrieval
                                      |
                                      v
                              Relevant chunks only
                                      |
                                      v
                              Groq or Gemini
                                      |
                                      v
                         Grounded answer + citations
```

## RAG Pipeline

1. The user uploads one PDF.
2. The backend validates its type, size, structure, and configured page limit.
3. Each readable page is cleaned and represented with document and page metadata.
4. Pages are split into token-sized chunks with chunk identifiers.
5. Chunks are embedded and stored in Chroma.
6. A lightweight keyword index is built for the active document.
7. Each question runs semantic and keyword retrieval.
8. Results are deduplicated, ranked, and filtered by the relevance threshold.
9. Only the final relevant chunks are sent to the selected LLM.
10. The backend attaches source metadata to the answer.

## Hybrid Retrieval

Semantic retrieval uses Chroma similarity search. Keyword retrieval uses a lightweight in-memory BM25-style index scoped to the active document. The application combines both result sets, removes duplicate chunks, ranks the evidence, and selects only the configured number of final chunks.

The normal UI does not expose retrieval scores, chunk IDs, or raw debug data.

## PDF Processing

The processor validates:

- `application/pdf` content type
- `.pdf` filename
- Maximum file size
- Actual PDF structure
- Actual page count
- At least one page

The page limit is configurable and defaults to 2,000 pages. Documents smaller or larger than 300 pages are supported subject to this limit and available system resources. Pages without extractable text are reported as warnings; OCR is not included.

## Embeddings and Chroma

Groq uses the local HuggingFace `sentence-transformers/all-MiniLM-L12-v2` embedding model. Gemini uses Google GenAI embeddings. Chroma persists the active provider's chunks under the configured data directory. Uploading a replacement document removes the previous active vector store before creating the new one.

## LLM Providers

Groq is the default provider and uses the official `langchain-groq` integration with model `openai/gpt-oss-20b`. Gemini remains available as an optional provider through `langchain-google-genai`.

API keys are read by the FastAPI backend only. The Streamlit frontend never receives or stores provider keys.

## Citations and Follow-ups

Citations come from retrieved chunk metadata, not from text generated by the LLM. Each source includes document name, page range, chunk ID, retrieval score, and retrieval method in the API response. The frontend presents the document name and page.

The chat request can include a small history of previous turns. Follow-up questions such as `What about international customers?` use the previous question as lightweight retrieval context.

## Configuration

Copy `.env.example` to `.env` and set the required provider key:

```env
RAG_ENVIRONMENT=development
RAG_LOG_LEVEL=INFO
RAG_LLM_PROVIDER=groq
GROQ_API_KEY=your_groq_api_key_here
RAG_GOOGLE_API_KEY=your_google_api_key_here
RAG_MAX_PDF_SIZE_MB=200
RAG_MAX_PDF_PAGES=2000
RAG_ALLOWED_FILE_TYPE=application/pdf
RAG_SEMANTIC_TOP_K=8
RAG_KEYWORD_TOP_K=8
RAG_FINAL_TOP_K=5
RAG_MINIMUM_RELEVANCE_SCORE=0.15
```

`GROQ_API_KEY` is required when Groq is selected. `RAG_GOOGLE_API_KEY` is required only when Gemini is selected. The application does not require both keys simultaneously.

## Installation

From the repository root, create and activate the existing virtual environment or create a new one:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r server/requirements.txt
python -m pip install -r client/requirements.txt
```

## Running the Backend

Set `GROQ_API_KEY` in `.env`, then run:

```powershell
.venv\Scripts\Activate.ps1
cd server
uvicorn main:app --reload
```

The API runs at `http://127.0.0.1:8000`.

## Running the Frontend

In a second terminal:

```powershell
.venv\Scripts\Activate.ps1
cd client
streamlit run app.py
```

The Streamlit application will display its local URL.

## Testing

Run from the repository root:

```powershell
.venv\Scripts\Activate.ps1
python -m compileall -q server client tests
python -m unittest discover -s tests -v
python -c "import sys; sys.path.insert(0, 'server'); import main; print(main.app.title)"
```

Tests use mocked LLM responses and do not require a paid Groq or Gemini request.

## Example Usage

1. Select Groq and `openai/gpt-oss-20b`.
2. Upload `CompanyPolicy.pdf`.
3. Ask: `What is the cancellation policy?`
4. Receive an answer such as: `Customers can cancel within 30 days.`
5. Verify the displayed source: `CompanyPolicy.pdf - Page 42`.

## Error Handling

The API returns simple user-facing errors for invalid PDFs, documents above configured limits, missing documents, and provider failures. Detailed exceptions are written to backend logs only. Internal paths, stack traces, and API keys are not returned to the frontend.

## Security and API Keys

- Provider keys are loaded only by backend settings.
- `.env` is ignored by source control; `.env.example` contains placeholders only.
- Uploaded files and generated vector data are ignored by source control.
- File type, PDF structure, file size, and page count are validated.
- User questions are treated as text and are not executed as code.

## Current Limitations

- OCR is not included for scanned PDFs.
- The keyword index is in memory for the active document.
- The application is designed for one active document, not multi-document search.
- Grounding validation is lightweight and heuristic.
- Authentication and deployment configuration are outside this project.

## Future Improvements

Possible future work includes stronger evidence verification, OCR as an optional processing path, persistent session isolation, retrieval evaluation, and operational deployment configuration.
